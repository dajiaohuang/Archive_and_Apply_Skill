# Resume Wording Constraints

Read this reference with `resume-bullet-writing.md` when drafting or locking resume bullets, especially bilingual Chinese/English files.

These rules come from locked resume passes. They restrict what may appear on the resume; they do not replace source-first evidence rules.

## Ownership and labels

- Do not start every project bullet with “独立设计” / “Independently designed”, even when the source supports full ownership. State ownership once, in the bullet where the design claim is the point.
- Keep one job per bold label. Do not nest a second colon after a label (`**标签：** 再解释一件事：`).
- Do not hitch a second action with “并以…”. Use a new clause, a semicolon, or a new sentence.
- Do not stack jargon in the opening clause. Name the recognizable problem or split first; put protocol and product names later.

## What stays in the fact layer

Keep these out of final bullets unless the user explicitly asks to restore a specific number:

- protocol dates, schema versions, auth versions, and internal payload versions
- unevaluated, internally designed, or unpublished scores; write the scoring criteria or gates instead
- parallel inventory counts across subsystems (for example three tool-catalog sizes) when one representative scale number is enough
- raw activity volume as the headline: PR totals, commits, tickets, files touched
- invented adoption, download, install, or user-count metrics for personal skills and tools
- activation, lease, multi-track memory, and other implementation vocabulary that the bullet does not need
- a capability claim the source has not measured (for example “full snapshot can restore without replay”)

Stars, forks, and similar repository metrics describe the upstream project, not the candidate. Date-stamp them and recheck before a resume release.

## Evolution and history

- Preserve an iterative narrative. Do not delete an earlier route from the resume only because a later design replaced it.
- Do not label an organic evolution as “第1/2/3代” or “generation 1/2/3”. The first historical practice is original practice, not a designed generation.
- A later architecture may keep a small representative number from the primary path (for example one game system's tool-projection cap) and leave the other systems' inventories in the fact layer.

## Cross-section and variant rules

- If the same project appears in two sections, give each placement a different job. Do not reuse the same result sentence.
- In a combined open-source block, a core-contributor runtime project may stay last even when it has fewer stars than third-party upstreams.
- Language and page-count variants may omit a project. They must not contradict a locked claim or promote open/unmerged work to “accepted”.
- Prefer the reader-facing local term on a Chinese resume when the English product name is not the public name (for example 场景图谱, not Scene Atlas).

## Publications

- Use the official paper title, not a shortened resume title.
- If the author list is omitted, write the authorship role (`共同作者` / `Co-author`).
- Do not add equal-contribution or corresponding-author marks unless the source paper supports that exact meaning.
- Dataset totals on a publication line are paper-level facts. Do not imply they are the candidate's personal processing share unless the experience source says so.

## Skills section

- Lock skill wording with the rest of the resume. After the full lock, compress the skills **layout** (row count, type size, gaps) before rewriting the words.
- Keep a skill only when some other entry can defend it.
